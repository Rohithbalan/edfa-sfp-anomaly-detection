## How to run

The project needs Python 3.10 or later. It was developed and tested on Python 3.11.11.

**On Kaggle.** Attach the competition data to the notebook and choose *Run all*.

* The code finds the raw files under `/kaggle/input` automatically, whatever the dataset folder is called.
* Outputs go to `/kaggle/working/outputs`.

**Locally.**

```bash
python -m venv .venv && .venv/Scripts/activate      # or: source .venv/bin/activate
pip install -r requirements.txt
# put the three raw files in ../ML Test Data/ (any depth), or point to them:
#   export PDM_DATA_DIR="/path/to/folder/with/the/csvs"
python run.py                                        # runs Parts A-E, writes outputs/
python tools/build_deliverables.py                   # optional: rebuild the notebook and the .md exports
```

`run.py` is the single source of truth: the notebook `pdm_notebook.ipynb` is generated from it with jupytext and executed with nbconvert, so the two cannot diverge.

**Runtime and hardware.** The full run from the raw CSVs takes **93 s** as `python run.py` and about **2 min** as an executed notebook. Measured on a laptop: Intel i5-8365U, 4 cores, 16 GB RAM, CPU only, Windows 11. No step needs caching.

## Approach in one paragraph

* **Wrangling.** Readings are aligned to 1-minute polling slots. Unmapped SFP ids are kept and their role is inferred from their values. Every sensor is classified using its name and its data together.
* **Preprocessing.** Physically impossible values are logged as point anomalies and then masked. Optical readings are masked during ICMP outages, with a guard period. The SFP `Current` window is chosen after showing that `Current Day` is corrupted and that `Previous 15min` carries a clock offset. The data is resampled to 5-minute (EDFA) and 15-minute (SFP) medians.
* **Detection.** The EDFA detector is a set of 1–3-coefficient physics-residual models: cooler current given case temperature, pump current given PIN and temperature, pump power per mA, and pump temperature against its set-point. Residuals use robust z-scores with physical floors, an alert needs 15 minutes of persistence, and an incident stays open until the condition has been clear for 6 hours.
* **Evaluation without labels.** Five injected fault types, including two negative controls; agreement with an Isolation Forest; and validation against an independent data-integrity rule.

## Headline results

* Only 22 of the 88 days carry EDFA optical telemetry. There were collector gaps of 23 and 21 days across all assets, and the devices themselves never rebooted.
* A site-level heat event (both EDFAs 7–9 °C hot for 44 hours) was correctly *not* alerted: the cooler responded exactly as case temperature predicts.
* All EDFA and SFP alerts trace back to level shifts with a monitoring signature. They start at 00:00 UTC, introduce values off the sensor's grid, appear in one SFP reporting window only, or contradict the physics. No device fault is confirmed.
* Injected faults:

  | Fault | Physics detector | Isolation Forest |
  |---|---|---|
  | Pump ageing ramp | 24/24 (alerts at about 2% drift) | 0/24 |
  | Cooler fault | 23/24 | 0/24 |
  | Pump-power drop | 12/12 | 0/12 |
  | Explained hot afternoon (control, should not alert) | 0/24 | 8/24 |

* The most actionable maintenance item is thermal: both SFP lasers warmed by 8 °C between January and March, which leaves roughly 16–18 weeks of margin to an assumed 70 °C limit before summer.
